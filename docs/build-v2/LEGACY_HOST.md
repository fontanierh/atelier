# Continuous legacy authority parent — implementation checkpoint

This operational host composes with the existing Python scheduler; it is not another scheduler,
cache, worker, admission service or rollback mechanism. The original v2-only route is unchanged.
The new entry is private and must not be activated until the coupled Python provider, source
origin, launch custody and complete normal-selection acceptance are reviewed and passing.

The host retains actual checkout build/EX and anchored checkpoint-writer locks. Its one owned
lightweight Python scheduler holds passive duplicates of those same open descriptions. All
ordinary native descendants still require their own existing admission and supported custody
monitors. No lock is adopted from a descriptor number and no manual unlock is introduced.

A version2 marker spans Prepared, bounded active frames and finalization. Original task recovery,
restore, stamp migration, batch preparation, discovery/control writes and finalizers need an exact
qualified scope before mutation. Per-member stamps while a shared worker lives are provisional;
positive shared guard cleanup and fresh member checks precede settlement. Frame changes use
rename-over, never a finish/begin gap. Active caps remain64tasks/16roots/128writes per task,
256attempts/256KiB record/1024witnesses per check. Every durable transition consumes the explicit
MAX_TRANSITIONS=65,536 operational limit; this is not a measured graph-size claim.

A normal source-fix rerun uses Supersede under the same real guards, checks every recorded
attempt's cleanup and carries every old attempted-unsettled physical/canonical claim into a
qualified new-source closed replay or exact supported recovery scope. It gives no old settled
credit and never resets the counter, trims claims or treats an output-absent attempt as unstarted.
Unknown cleanup, changed anchors, unsupported removed/retargeted tasks and overflow stay fenced.
A Prepared-only shortcut requires that no permission was ever issued, even across earlier frames.

The frozen controller distribution is independently rehashed with the existing explicit capture
algorithm and must match the binary's compiled source identity. The separate captured game
issuer is an explicit semantic trust boundary: matching named source bytes identifies the provider;
it does not prove arbitrary Call/native semantics. Actual code-object/helper/settings provenance
and normal complete graph validation are required in the coupled Python implementation.

The strict version2 protocol is a single nonreconnecting channel with bounded messages and live
exact-duplicate reply caching. Durable permission precedes ACK. Lost or malformed replies permit
no new task/launch/retry. After all scoped finalizers and a pure complete graph validation, Finish
records complete, removes the exact own fence and fsyncs. A lost final ACK is caller unknown/failure;
there is no new terminal receipt or cross-host permission replay.

Current source-checkpoint gaps are explicit: the caller/provider and final graph streaming are
being integrated separately; old version1 records refuse rather than migrate implicitly; external
output roots require explicit authority; C7 pressure/selection-loss archive chains currently return
unknown cleanup rather than trusting only the final PID. Missing guard receipts are never evidence
of no launch. No cold/default graph coverage, native geometry or parent-death acceptance follows
from the bounded Rust fixtures. MAC1 native validation remains deferred. Failed trials, retained
claims and earlier source/evidence are preserved.

Both processes use the explicitly tagged `posix-clock-monotonic-v1` domain: Rust
`clock_gettime(CLOCK_MONOTONIC)` and Python `clock_gettime_ns(CLOCK_MONOTONIC)`. Darwin's
`time.monotonic_ns()` uses another numeric origin and must not be mixed with it. The host
resamples the shared absolute clock before every poll/read/write, source check and shutdown
bound; it does not retain a conversion to `Instant` across sleep. An unknown tag refuses.

A fresh default checkout needs no prior plan invocation: under real build+EX, the host may
create only the empty canonical `build/{project}` directory chain required for its third lock.
It validates the captured original game's strict name and rejects aliases, special paths,
external roots and arbitrary missing overrides. This creates no Content, stamps or payload.
Private captured game-provider bytes must also match every original named checkout source;
those freshness witnesses remain mandatory in the selection. A private capsule hash alone
cannot substitute a different provider or omit its code/helper closure.

Guard cleanup now requires a counted `guard_returned` observation from the exact captured
provider that actually observed a normal outer automatic-full-capacity `guarded.run` return.
That is a provider capacity-close attestation, not a guard-issued receipt or code-zero success.
The host independently binds actual raw process/tree hashes, child/start/monitor/controller,
host boot, unique invocation namespace and all three actual lock identities. Wrapper
`cleanup.json`/`custodian.json` selfassertions and optional timing diagnostics are insufficient.
Nonzero normal return may establish cleanup but cannot settle an ordinary task as successful;
only a separately verified completed member of a supported shared batch can retain its result.
An exception, lost provider or missing observation stays unknown. Pressure archive chains still
refuse until their complete positive evidence is supported; missing files never prove no launch.

Dirty claims clear only after exact-file/absence or complete bounded tree disposition. One
arbitrary descendant or a directory inode cannot establish a repaired old subtree. Work requests
stop at overall deadline minus the reserved cleanup interval; shutdown keeps the whole bound.
Linux sanitizes the complete child FD table using CLOEXEC-only close_range. Darwin inventories
actual descriptors independent of soft limits and relies on this private standalone single-thread
source callgraph; no arbitrary threaded embedding or atomic Darwin std-pipe claim is made.

This is a correctness boundary for the exact trusted frozen provider, not a forgery-proof boundary
against a malicious same-UID scheduler that can fabricate files or write the private pipe. On any
partial-frame/transport ambiguity the host closes permission immediately; it sends no replacement
Refused frame that could consume the cleanup reserve. A previously validated complete covering
directory inventory proves an old covered child either present or absent, without inventing a
contradictory absent child inside that inventory.

Startup now carries the original lexical interpreter role separately from the canonical image
and its hash. The host launches that role verbatim with `-I -S`; it never assigns a synthetic
`sys.executable`. The captured original constructor supplies `python_context` with its actual
C2c platform roots and explicit `purelib`/`platlib`. Rust retains lexical scheme spellings and
checks real existing-directory containment, including refusal of missing schemes. This metadata
validation does not independently discover or certify the original interpreter's sysconfig.
The captured bootstrap must apply the vetted context without `site`, `.pth` or editable hooks.

`operational_environment` is a required closed object containing `agent`, `cache`, `build_root`
(each explicitly nullable), and vetted `path`. The launcher clears its inherited environment
before applying only `ATELIER_AGENT`, `ATELIER_CACHE`, `ATELIER_BUILD_ROOT` and `PATH` values;
it refuses unknown fields and empty/relative/missing PATH directories. Unsupported original
overrides must be refused by the captured constructor rather than silently omitted. No new
source key, worker context, controller-order/repair permission or native execution is introduced.
The three Rust startup tests exercise the real command factory and metadata validators without
claiming an actual Python launch or production-discovery proof; the coupled hosted entry test
must establish the latter separately and stop at typed Held/Unsupported, without Finish.

framed issuer digest; it must not rediscover a live closure or substitute an unbound sidecar list.
