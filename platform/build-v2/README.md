# Build v2 interfaces (A0)

This unused Rust library is the shared interface for the build-v2 tracks. Production v1 is unchanged.
Declaration schema **1**, result schema **2** and protocol version **1** are the wire contracts; incompatible changes
require a version bump and coordination with consumers. The lockfile pins this crate's dependencies,
not game cache identities.

- `schema`: `Declaration`, `Unit`, `Input`, `Item`, `ResultRecord`, `IdentityIngredients`.
- `protocol`: `JobRequest`, `Request`, `Response`, `read_frame`, `write_frame`.
- `fixture`: `Worker`, `MockWorker`, `MockStep`, `FixtureFile`.

[examples/units.toml](examples/units.toml) is a complete parseable declaration. Code lists are explicit,
project-relative and include the entry script. Loading undeclared project code will be refused by the
later worker adapter. A selector is an RFC 6901 JSON pointer. References identify logical path and class,
name their proof test and optionally link a producer item for scheduling; producer bytes are not reference
identity. Content inputs link a file/selector or a producer unit/item. File sources explicitly mark optional inputs; `ContentIdentity::Absent` differs from any digest, including
an empty file. Item `files` is the complete permitted set: each `OutputFile.path` is job-output-relative,
`install_path` is checkout-relative, and `required` defaults to true. Optional native sidecars set it false;
`StoredItem.files` records the exact emitted set. A2 validates required outputs and install ownership. External outputs allow a later Zen adapter to name its locator.

These are **unvalidated data types**. A2 adds semantic validation (versions, paths, closure, graph,
ownership, op registry); A3 computes keys. Digests are opaque strings here. `ResultRecord.key` is the
producing input key; each `StoredFile.digest` is that exact file's content digest. Worker and validator
versions and digests are explicit identity fields. Checkout/branch/commit/dirty/time live only in provenance.

Frames are a four-byte unsigned big-endian byte count followed by UTF-8 JSON, at most 8 MiB:

```json
{"version":1,"message":{"type":"shutdown"}}
```

Requests: `run` (one `job`), `cancel` (`job_id`), `shutdown`. Responses: `hello` (`worker_version`),
`started` (`job_id`), `completed` (`job_id`, `outputs.files`), `failed` (`job_id`, `failure.kind`,
`failure.message`), `stopped`. Protocol JSON carries paths and metadata, never asset bytes. Run jobs
name a staged `job_dir`, relative script/code/input paths, parameters and allowed outputs (with required/optional status) under
`output/`. Logs use stdout/stderr, never the protocol pipe. C1 owns session ordering and staging;
C5 owns retries, deadlines and guard-stop policy. A0 never interprets a returned path as validated.

`MockWorker::new` takes ordered `MockStep`s. `Worker::run` records each request, returns scripted
paths/failures and keeps generated bytes in `produced()` for the harness. Unknown or out-of-order
jobs fail. A step can return any failure class or arbitrary files (including a plan payload). More
elaborate hooks and pending/crash processes belong to A8; this mock does no filesystem or native work.

Local compile/tests must use the standalone compile admission described in
[BUILD_CAPACITY](../../docs/BUILD_CAPACITY.md#standalone-native-tool-builds), with three workers.
Run from this crate directory so `.cargo/config.toml` places generated files in `build/build-v2/`:
`cargo test --locked`. Compilation time and test execution time are reported separately.

## T0 CI (A1)

Every PR runs the `Rust / T0` hosted job. It compiles the current crate with three workers, then runs
pinned cargo-nextest 0.9.149 with profile `ci`: a ten-second global test timeout, no retries and no
ignored tests. Compile time is reported in its own step. The job retains collection JSON and JUnit
execution/timing artifacts; neither a cached binary nor an empty test run can provide success.

`tests/registry.toml` maps each active scenario to nextest IDs (`binary-id/test-name`). The hook
checks that collection and execution cover exactly those tests once, with no ignored, filtered,
skipped, failing or unmapped tests. Add an active row with each new T0 scenario; use the named
scenario IDs in future engine tests. Future required scenarios remain explicit `pending` rows with
their implementation tasks. A pending row is a gap, not a pass. A8/H5 will activate those rows as the
engine/reference model is implemented; A1 does not claim the full TESTING scenario suite exists.

The registry checker is a read-only Python tool. Its focused tests run in ordinary Python CI:
`uv run pytest platform/studio/tests/test_build_v2_registry.py -q`. A local nextest compile/run must
still use the standalone admitted compile workflow; the CI profile is not a memory/admission guard.

## Declaration validation (A2)

`validate::load` parses TOML and checks it against caller-supplied `OpRegistry`, `SourceSnapshot` and
allowed checkout install roots. `validate::validate` checks an already parsed declaration. The registry
names supported op/version pairs, their named input roles/requiredness, optional-file/selector policy,
accepted input-item classes, output classes and named parameter types/requiredness. Missing definitions,
unknown names and invalid top-level parameter types fail; nested domain constraints belong to each op.

The snapshot is an immutable map of exact project-relative file names to frozen bytes or an explicit
non-regular/unreadable state. Absence is a missing entry; it is permitted only for an explicitly optional
file accepted by the op. Missing JSON selector nodes always fail when the file exists, including when
that file is optional. Successful validation returns dependency order and resolved whole/absent/selected
file observations. It does not hash inputs, discover imports, walk the live checkout, stage files, launch
workers or decide cache hits. The snapshot provider must include the real ignored/untracked inputs and
establish physical path provenance; later A3/C1/A6 bind bytes, enforce loaded code and check mid-build edits.

Paths must be relative, with no empty/dot/traversal components, backslashes, drive colons, controls or
trailing dot/space aliases. Logical output/reference paths start with `/`. Source Unicode names retain
exact spelling. Owned-path collision comparison uses canonical Unicode decomposition and full non-Turkic
case folding, then decomposition again; it rejects equal and ancestor/descendant ownership, including
optional sidecars. This is a conservative portable collision policy, not an emulator of every APFS
Unicode revision. Representative ASCII case and composed/decomposed aliases and ancestor conflicts were
also checked with exclusive file creation on the local case-insensitive filesystem. Full physical-path
and native receiving acceptance remains a pre-cutover responsibility; validation alone makes no claim
about symlink aliases outside the supplied snapshot or every filesystem's Unicode rules.

Job-output names are scoped to one unit's scratch output; checkout install ownership is global across
the declaration and must stay under the caller's allowed roots. Raw/store paths may therefore match a
finish unit's logical asset identity without sharing mutable outputs. Checkout logical owners are
unique. Neither code nor declared file inputs may overlap checkout installs. A unit's entry script must
be listed in its explicit code closure, but the validator does not pretend that this proves all dynamic
imports are declared. Content and linked-reference producers must exist; linked references must agree
on logical path/class and carry a proof-test name. Broad/aggregate op slots marked
`require_whole_reason` require a nonempty rationale; already bounded payloads, FBX or narrow query
results need no boilerplate note. The op definition and recipe review establish that classification.
Producer scheduling cycles fail.

Focused cases in `tests/validation.rs` cover absence, selectors, missing or non-regular inputs, op rules,
producer identity, cycles, invalid paths, Unicode collisions, disjoint output ownership and install roots.
The library remains unused by production v1. Its tests run in hosted Rust CI; local compilation still
requires ordinary standalone compile admission.

## Immutable objects (B1)

`store::ObjectStore::open(root)` uses an explicit trusted store root. Object format **1** stores
payloads at `objects/sha256/<64 lowercase hex characters>`. It has no default machine path and no
production callers. Changing algorithm or encoding requires a new format/namespace.

`prepare(source)` clones a regular source into a newly reserved private staging directory, freezes
the snapshot read-only, hashes its exact bytes once and returns a private `PreparedObject` token.
`publish(token)` accepts only a token from the same store and publishes with macOS `RENAME_EXCL`.
The first entry wins; an existing regular read-only entry is kept, with a cheap size check. Existing
object contents are trusted on ordinary hits; B7 owns explicit corruption verification and recovery.
A dropped/failed token cleans only its own staging payload and empty private directory. Source files
remain unchanged. This is not a result transaction: B2 must lease before calling prepare and retain
that lease through its publication/record lifecycle. No cleanup, root or result-record engine exists here.

`clone_to(digest, destination)` uses APFS `clonefile`, never rehashes or scans, refuses an existing
destination and never copies bytes as a fallback. Unsupported platforms/filesystems and other clone
errors are explicit failures. The cloned payload is read-only; B2/B3 must retain/install source modes
from the publication receipt (including executable permissions) as result metadata. B1 stores bytes,
not checkout install policy or file-mode identity.

The Rust job now runs on Linux and macOS. Registry `platforms` may contain only `linux`/`darwin`;
selection uses the host triple recorded in nextest's listing, so downloaded evidence is interpreted
independently of the reviewer's machine. Excluded-platform scenarios are reported separately, never
counted as passes. Linux tests prove explicit unsupported behavior; mandatory macOS tests prove real
APFS cloning, independent edits, read-only snapshots, no-replace races and owned cleanup. Both jobs
keep compile time separate from the ten-second T0 run. Local native repetition is reserved for a
specific CI coverage gap or diagnosis, through the ordinary admitted compile workflow.

## Unit keys and source hash hints (A3)

`keys::prepare` consumes an A2-validated declaration, the same frozen source snapshot, explicit
worker/validator code identities, current produced-item manifests and a complete staged-slot map.
It returns an immutable `PreparedUnit`: the SHA-256 key, typed ingredients, input staging payloads
and a `JobRequest` template. The library remains unused by production builds.

Keys use a domain/version-tagged canonical JSON encoding: recursively sorted object keys, sorted
code/output memberships and exact primitive/array data. Ingredients include cache/op versions,
selected entry script plus declared project-code hashes, worker/validator versions and code hashes,
semantic parameters, logical output identities, content identities, references and staged paths.
Installed Python/libraries/lockfiles, Blender/add-ons, Unreal and compiler/SDK versions are not
implicitly discovered or hashed. Platform invalidation requires explicit op/cache version changes.
Project-owned settings/code remain declared inputs. Provenance and stat hints are outside identity.

A content dependency consumes the exact saved file manifest: relative member names, byte SHA-256,
size and normalized semantic mode. It never consumes the producer's input key, source closure or
capture provenance. Missing required members fail. External/Zen items need their future typed adapter;
this API refuses to invent their content identity. References bind only logical path/class; their
staged descriptor contains exactly those fields, never referenced asset bytes.

Raw files stage exact bytes. JSON selectors stage canonical bytes of the selected value with its
actual shape, without source locator or selector text. Optional absence is an explicit absent identity,
not an empty file, JSON null or missing node. Missing selector nodes still fail validation. A source
locator/selector rename that preserves this staged view leaves the key unchanged.

**Worker-visible staging contract:** every declared slot has one explicit safe relative path. Raw,
selected and reference-descriptor inputs use that file name (including extension); multi-file items
use a directory root with their exact recorded member names. Equal/casefold/normalization/ancestor
collisions fail across staged slots, project code and the reserved writable `output/` tree.
Code retains its declared relative paths; neither code nor inputs may occupy `output/`. The same
conservative normalized path policy is shared with A2. This full map enters result ingredients and
keys, and `request()` emits precisely its
`StagedInput` names/paths/identities. Source/code data files stage read-only with canonical mode 0444;
item members preserve their semantic executable distinction (read-only 0444/0555 while staged).

C1 must implement this boundary: it may not inject original source locators, selector text or producer
history through Run fields, parameters, logical input objects, environment or helper APIs. Parameters
are the declared semantic parameters, not an implicit metadata channel. The op sees only the hashed
staged view. Job ID, job directory and unit scheduling label remain controller/logging metadata and
must not influence semantic output. The pending `c1.staged-view-semantic-independence` scenario requires
actual worker output equality under different control metadata and source locators; logs may differ.
A3 tests establish encoding and Run mapping only, not that future workers already enforce isolation.

**Result schema 2:** `IdentityIngredients.script` identifies the selected entrypoint even when the code
closure is unchanged; `staged_inputs` records the visible slot map and `input_kinds` binds each slot
as a file or item directory, even if content digests coincide. `StoredFile.mode` is 0644 or 0755.
B1 blob hashes remain byte-only and stored blobs immutable. B2 must normalize captured source mode
(any execute bit becomes 0755, otherwise 0644), retain it in result records and compare it for conflicts;
B3 must restore semantic modes before publishing checkout installs. C1/B2/B3 and package tests must
prove those mode rules. General ACL/xattr handling is outside this format. Old result records lack
these required fields; B2 must reject unsupported result versions rather than infer missing metadata.
Declaration schema and worker framing protocol remain version 1.

`SourceHashCache` hashes each frozen whole-file or selected-view version once. Its advisory version
hint includes device, inode, size, nanosecond mtime and ctime; selector hints also identify the selected
view and its explicit encoding version. A changed view codec must bump that version before reusing hints.
Hint metadata never affects the semantic hash. A changed ctime defeats an unchanged-size/mtime
hint. Missing hints hash bytes; missing/corrupt checksummed hint records become empty caches. The
snapshot provider must bind stat tokens to those same frozen bytes. The checksum detects damaged
hint records; it is not a hostile-input trust boundary. Live source snapshotting, input rechecks,
mid-build rekeying, actual scheduling cutoff and clean-build oracle integration remain later work.

`tests/keys.rs` covers the identity boundaries, selected-data cutoff, reference independence, semantic
modes, staged paths, dispatch metadata, manual invalidation, source-version reuse and damaged hints.
The broad engine scenarios in the registry remain pending until the engine/reference model exists;
these pure tests do not claim A4/A6/A9 end-to-end execution behavior.

## Failure policy (C5a)

`failure_policy::JobPolicy` makes pure per-job decisions from caller-supplied monotonic times and
controller-side `Event`s; it reads no clock, never sleeps and launches or signals nothing. Only a
controller-observed unexpected exit on the first attempt is retry-eligible; the retry waits for
confirmed cleanup and then asks for a fresh admission (`RequestAdmission`), launching only after
`Admitted`. A worker's own `failed` claim, including `crash`, is never crash evidence. Job, dependency
and protocol errors, cancellation, job-limit and overall-deadline timeouts, guard stops and cleanup
timeouts do not retry. The job limit starts at each admission; the optional overall deadline runs from
submission over queue, execution, cleanup and retries. `BeginCleanup` is a request limited to the
owned process and unpublished scratch, and an `Unconfirmed` cleanup outcome means the process may
still be alive. Real owned-process cleanup (C5b) and capacity/guard integration (C7) remain pending.
The decision matrix is in `tests/failure_policy.rs`.
