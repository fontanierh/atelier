# Sandbox

The smallest game on Atelier: a flat test ground with a few blocks and a character made of basic shapes, used to try
the platform's plugins and commands without Yorimichi. It shares no files with other games; everything it uses from the
platform goes through the same doors a new game would use.

```sh
atelier build sandbox                    # compiles the module and makes the level (a couple of minutes)
atelier play sandbox                     # WASD or a left stick to move, mouse or right stick to look, Space jumps
atelier live state                       # the live bridge answers (LiveBridge plugin)
atelier stream sandbox start --local     # the plain player at http://127.0.0.1:8080/ (Pixel Streaming 2)
```

What it shows about the platform:

- a second `game.toml`, build recipe and Unreal project, found by the same `atelier` commands;
- the live bridge (runtime GLB props, `atelier live`) and the stream's plain player working with no game code beyond
  `AtelierLive::Start` and the settings in `unreal/Config`;
- the plugins found through the uproject's `AdditionalPluginDirectories`, like any game.
- a cached block library (`world/block.json`) and separate placement records (`world/placements.json`). Moving
  a block rebuilds placement and the level; its geometry product stays current. Changing the block's size
  regenerates its shape and bounds without regenerating placement. Both generators have complete named products
  and opt into Python file-access auditing; undeclared reads and writes prevent certification.

`atelier build sandbox world` exercises these portable products without Unreal. Successful actions publish to
the machine's local product store automatically; a missing output is verified and restored on the next build.
`atelier build sandbox world --plan --explain` reports decisions without changing files. Use `--verify` to read
all bytes instead of using the disposable local hash index. See [build recipes](../../docs/BUILD_RECIPES.md).
Executed generators also produce `build/sandbox/logs/<step>.audit.json`. The audit accepts declared inputs and owned
writes, with private temporary files for atomic replacement. Cache hits do not execute another audit. The recipe
guide describes the Python-only scope and the remaining metadata, environment and native-I/O limits.
`atelier build sandbox world --timings` reads the last successful receipts. The block generator emits separate
read/validation and output-writing phases. Cache restoration shows its own duration and preserves a known local
producer receipt; a fresh checkout restore reports producer timing as unknown. Add `--json` for structured output.
`atelier build sandbox --ddc` reads retained Unreal logs for DDC configuration and recorded counts. Until those
native logs exist it reports unknowns; inspecting them never starts Unreal or modifies caches.

`world.block` declares the optional source `world/block.override.json`. When present, its JSON object overrides
fields from the required `block.json`; for example, `{"size_cm":[100,200,400]}` changes the dimensions. Creating,
editing or removing this exact file updates the block products without rebuilding placements. Other files in
that directory do not invalidate the block. The default is absence, which has its own reusable cache identity.
Commit the override when it is part of the intended game; it is a source file, not a generated output.

With no override, changing `world/block.json` and building again makes `atelier build sandbox world --changes` list the changed shape
and bounds members. Placement stays current. Restoring a missing block output from the cache reports no content
change when it matches the previous certified inventory. The first build reports an unknown baseline.

Everything under `unreal/Content` is generated by `Scripts/make_level.py`; engine basic shapes are referenced, not
copied.

## Spatial dependencies without Unreal

```sh
atelier build sandbox spatial.demo
atelier build sandbox spatial.demo --plan --explain
atelier build sandbox spatial.tile.west
```

These explicit steps run small audited Python actions, without compiling or starting Unreal. Three sources in
`world/spatial/` each produce geometry and a separate preview. Two tiles query neighbouring geometry using
centimetre bounds in the same coordinate frame. They consume the frozen matches from `atelier.build_context`.

Change the west source's `shape`: its producer and the west tile rebuild. Change only `preview_colour`: the
producer rebuilds and both tiles stay current. Change the far source: neither tile rebuilds. Move the west source
by changing `bounds_cm` to `[120,-10,-10,130,10,10]`: both its former west tile and its new east tile update.
Adding or deleting a source also changes the matching tiles, including a tile whose result becomes empty.
Boxes touching a tile boundary count as neighbours on both sides. Restoring an earlier source state may restore
its already certified tile from cache instead of executing it again.

Normal sandbox builds exclude this example. Targeting a single tile selects only its matching source producers.
The example validates dependency selection and cached outputs; its JSON shapes do not certify geometric bounds
or any native world. Authors must declare conservative bounds and the full reach of their actual operation.
